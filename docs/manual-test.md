# 手工验收清单

本清单用于 MVP 手工验收。逐项记录系统、版本、网络环境、结果和日志；尤其要区分本机协议检查、LAN 客户端检查和 Xbox / Store 实机检查。测速数字只描述测试资源本身，不作为游戏下载速度验收指标。

## 1. 构建与初始化

- [ ] 运行 `./setup.sh`，分别选择本机与 Compose；确认引导包含安装目录、LAN IPv4、管理端口、可选的离线下载与本地回传，结束后显示可复制启动命令、WebUI URL 和 token。
- [ ] 在含空格的安装目录重复安装，确认更新生成物前会确认，原配置和 token 保留；Compose 在未选择启动时只初始化。
- [ ] 在 Linux amd64、Linux arm64、macOS amd64、macOS arm64 上构建可执行文件。
- [ ] 执行 `xdp init --data-dir ./data`，确认创建 `config.json` 和 `token`。
- [ ] 确认 token 每次首次初始化都随机生成，并且权限为仅当前用户可读写（Unix 模式 `0600`）。
- [ ] 再次初始化已有数据目录时，确认现有配置和 token 不会被静默覆盖。
- [ ] 用损坏或无效配置启动，确认错误可读、进程退出，不留下半启动的 DNS/HTTP/TLS 监听器。
- [ ] 确认配置更新校验失败时原配置仍完整，成功更新通过原子写入落盘。

## 2. Web/API 与管理认证

- [ ] 启动 `xdp serve --data-dir ./data --lan-ip <LAN-IP>`，确认默认只打开 Web/API。
- [ ] 新安装所有页面均显示醒目的“加速服务未开启”提示；应用节点后提示保持，启动成功后显示已开启。手机宽度下文字和启动按钮仍可见。
- [ ] 临时断开管理连接，确认显示“无法确认”并禁用启动按钮；恢复连接后状态自动更新。
- [ ] 确认启动输出中有访问地址和 token 提示；避免把完整 token 写入共享截图或公开日志。
- [ ] 从本机和另一台 LAN 设备打开 Web UI，输入 token 后可读写配置。
- [ ] 确认浏览器 token 使用 `sessionStorage`，刷新当前标签页仍有效，关闭标签页后需要重新输入。
- [ ] 用缺少 token、错误 token、正确 Bearer token 分别请求 API；前两者应拒绝，正确 token 应允许。
- [ ] 确认状态、配置、来源、导入、测速、应用、日志、健康检查等 API 错误响应清晰，且不会泄露 token。
- [ ] 确认管理操作仅影响相应配置/服务，无意外系统 DNS、hosts、防火墙或进程修改。

## 3. 监听生命周期和端口

- [ ] 检查 Web/API 默认监听地址和端口（默认 TCP 8080）。
- [ ] 用 `xdp start` 和 Web UI 启动服务，确认 DNS UDP/TCP 53、HTTP TCP 80、可选 TLS TCP 443 均按配置监听。
- [ ] 测试自定义高端口；确认 `--tls ""` 能关闭 TLS 监听。
- [ ] 启动前占用一个服务端口，确认启动失败指出冲突且关闭本次已打开的其他 listener。
- [ ] 执行 `stop`、Web UI 停止和进程退出，确认所有相应端口释放；再次 `start` 可恢复。
- [ ] 确认 `apply --group ... --ip ...` 保存配置后停止下载服务，重新 `start` 后才重新提供 DNS/HTTP(S)。
- [ ] 确认 `autoStart` / `--start` 的行为与配置和 CLI 说明一致。

## 4. DNS 与 HTTP(S) 行为

- [ ] 使用 `dig` 或 `nslookup` 明确指定本服务 DNS 地址，验证普通域名通过上游 DNS 解析。
- [ ] 为受控域名组指定测试 IP，验证 A 记录按配置返回；验证 IPv4 映射的 AAAA 查询按设计返回空答案。
- [ ] 验证 DNS UDP 和 TCP 查询均能响应；关闭服务后查询失败或客户端恢复到其他 DNS 的行为符合预期。
- [ ] 验证 Xbox HTTP 重定向的状态码、Location、路径和查询参数；在离线功能关闭时确认大文件由客户端直连 CDN。
- [ ] 验证 TLS 入口只按 SNI 转发字节流；证书仍由目标站点提供，未发生 TLS 解密、证书替换或 HTTPS 域名重写。
- [ ] 检查日志不会把 DNS 查询、HTTP 重定向或网卡总流量误报为游戏实时下载进度/速度。

本机可先用高端口验证，不需要占用系统服务端口：配置 `dnsListen` 为 `127.0.0.1:1053`、`httpListen` 为 `127.0.0.1:18080`，再用 `dig @127.0.0.1 -p 1053 example.com` 检查 DNS，用 `curl -v http://127.0.0.1:18080/` 检查 HTTP 响应。实际重定向域名行为应使用产品提供的受控域名配置检查。

## 5. 候选源、导入和测速

- [ ] 搜索 `广东 联通`、`联通 广东`、多个空格和 IP 片段，确认都可匹配 `广东深圳 联通`，同时排除广东电信、广西联通。
- [ ] 选择省份与运营商后自动测速，默认最多抽样 16 个且流量提示符合配置；无匹配时不自动选择其他地区，候选无地区标注时提示手选。
- [ ] 测速期间确认省份、运营商、域名组和应用按钮不可操作；结束后仅从成功且吞吐有效的样本推荐最快节点，取消后只参考已完成样本。
- [ ] 对每个可配置来源运行刷新，确认成功结果缓存到数据目录。
- [ ] 断网或使用无效来源 URL 再刷新：有缓存时沿用旧缓存并提示警告；无缓存时回退到当前 DNS 结果并提示警告。
- [ ] 导入空文件、无效 IP、重复 IP、IPv4/IPv6 混合列表，确认校验和错误提示合理。
- [ ] 测 `cn1` 默认测试资源；确认 `global` 使用其默认资源。
- [ ] `store` 未配置测试 URL 时确认清晰提示并避免发起无效请求；填写真实 URL 后确认可以测速。确认 cn2 默认测速 URL 可用。
- [ ] 确认 `--test-url` 只覆盖本次测试，不会意外覆盖分组配置。
- [ ] 测试可控的慢响应、超时、非 2xx、无内容长度和超出 `maxBytes` 的资源；确认并发和资源上限生效。
- [ ] 确认测速结果带有测试资源和测量含义提示，不声称等于实际游戏下载速度。

## 6. 离线诊断和日志

- [ ] 断网运行 `doctor`，确认只检查本机配置和端口状态，不依赖远端作者 API。
- [ ] 配置格式错误、端口占用、权限不足时，确认诊断提供可行动说明。
- [ ] 生成超过 500 条服务日志，确认内存日志最多保留 500 条，`logs --after` 可按序号读取。
- [ ] 确认秘密值（token、敏感请求头）不会被写入日志。

## 7. 容器部署

- [ ] 在 Linux NAS 本地执行 `docker compose build`，确认使用本地构建镜像。
- [ ] 确认容器使用 host 网络、没有 `privileged`，仅添加 `NET_BIND_SERVICE`，数据持久化到挂载目录。
- [ ] 检查 NAS 所需端口已空闲；占用冲突时服务失败且不影响原进程。
- [ ] 重建容器后确认配置与 token 保留。
- [ ] 默认下载目录挂载到 `./data/downloads`；设置 `DOWNLOAD_PATH` 后确认文件写入指定 NAS 卷，容器重建后文件仍存在。
- [ ] 记录 macOS Docker Desktop host 网络差异；macOS 服务端按原生方式验收。

## 8. 离线下载

- [ ] 提交可公开访问的 HTTP URL，确认创建任务并开始下载；提交 HTTPS URL，确认原站证书校验正常。
- [ ] Xbox/Store 下载域名作为来源时，确认连接使用已选 CDN IP，同时 HTTP Host、TLS SNI 与 HTTPS 证书校验仍对应原域名。
- [ ] 确认任务列表及 `GET /api/downloads` 返回任务和存储信息；记录文件系统总量、已用、可用空间、本工具占用量。
- [ ] 同时提交至少 3 个任务，确认最多 2 个处于下载中，其余排队；一个任务结束/暂停后，队列继续调度。
- [ ] 对正在下载的任务分别执行 pause、resume、cancel；运行中不允许直接删除，应先暂停。取消会保留部分文件且不能继续；delete 会永久删除任务元数据和对应文件。
- [ ] 下载支持 Range 的大文件，中途暂停再继续，确认通过 Range/If-Range 续传且已下载字节保留。
- [ ] 对不支持 Range 的源暂停再继续，确认任务从头开始；让资源 ETag/Last-Modified 变化后恢复，确认不会拼接不同版本内容。
- [ ] 下载过程中重启服务，确认原先 running/queued 的任务恢复为 paused，已完成/失败/取消的任务保留状态，只有用户主动恢复后才继续。
- [ ] 通过 `xdp download --source URL --name NAME` 新建任务，通过 `xdp downloads` 查看；验证 `download-pause`、`download-resume`、`download-cancel` 和 `download-delete` 的 ID 参数。
- [ ] 用 `download-save --id ID --output /local/path` 流式取回完成文件；断线后重新执行应从头取回，目标文件已存在时必须拒绝覆盖。
- [ ] 在剩余可用空间低于 256 MiB 时启动下载，确认被拒绝或暂停；对未知大小源持续写入，观察保留空间边界被正确执行。释放空间后由用户恢复任务。
- [ ] WebUI 使用浏览器流式保存能力取回大文件；在不支持该能力的浏览器确认 Blob fallback 对大于 256 MiB 的文件给出提示并建议 NAS 目录或 CLI。
- [ ] 对过期 Signed URL 验证明确失败提示，并确认创建新任务需用户提供新的 URL；服务不尝试登录、续签、获取商店目录或安装内容。
- [ ] 确认后台下载服务仅需 Web/API 运行，不要求启动 DNS/HTTP(S) 加速 listener。

## 9. Xbox 与 Microsoft Store 实机

- [ ] 记录 Xbox 型号/系统版本或 Windows 版本、客户端版本、路由器、运营商、LAN 拓扑和日期。
- [ ] 先保存客户端原 DNS 设置；将客户端 DNS 临时设置为服务端 LAN IP，确认无其他辅助 DNS 地址绕过优选。
- [ ] 分别检查 Xbox 下载域名组和 Store 域名组。对每组记录普通 DNS、指定 IP、重定向路径和客户端下载结果。
- [ ] 使用至少一个可重复的游戏/应用下载进行 A/B 对照，记录同一资源、相近时段的实际结果；不要用节点测速代替下载对照。
- [ ] 检查现有 IPv6 DNS 缓存、浏览器/系统加密 DNS 或客户端缓存是否绕过选择；按实际网络记录，不要求全面关闭 IPv6。
- [ ] 停止服务后将客户端 DNS 恢复为自动获取，确认普通网络解析和下载恢复。
- [ ] 记录已知局限、失败域名、可复现步骤和对应日志；未通过项目不应标记为实机验收完成。

## 可选离线下载与本地回传

- [ ] 新装不选择离线功能时，只运行原有节点加速，不创建下载队列；创建离线任务应返回明确的未启用提示。
- [ ] 安装时分别选择开启/关闭，确认 native 与 Compose 都保存正确的 offlineEnabled；重复安装留空保留原选择、token 和 autoStart。
- [ ] 在 WebUI 先停止加速服务，再开启离线功能并保存；确认下载页显示完整文件的回传条件、服务未启动提示。
- [ ] 捕获真实 Xbox 游戏的所有资源链接，暂停 Xbox 下载，等待 NAS 下载完成，再启动服务并继续 Xbox；核对 Xbox 最终完成下载、命中日志和实际发送字节。
- [ ] 用 Range/HEAD 请求原始资源，确认命中返回 200/206、越界为 416，任务文件名重命名不影响资源匹配。
- [ ] 删除或截断一个下载文件，确认不会发送残缺内容；缓存未命中仍可从 CDN 获取，不发生 DNS/302 循环。
- [ ] 同时验证已优选 IP、IPv6 网络、HTTPS 透传、Docker/NAS 标准端口和 LAN IP，避免流量绕过本地入口。
- [ ] 下载中关闭功能，确认任务暂停、文件保留；重新启用可手动继续。关闭后的 DNS 缓存过期后恢复原有直连/302 行为。
